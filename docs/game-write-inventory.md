# 区服写入入口与状态归属

| 写者与触发条件 | 可变对象 | 确认边界 |
| --- | --- | --- |
| UC 注册 | 账号、口令摘要 | UC 的 MySQL 自增主键发号；该 INSERT 提交成功并取回生成的 ID 后签发会话 |
| GAME 建角 | 账号到角色的目录、含建角区和当前区的玩家记录 | 将两者的首次版本、事实与角色请求回执同批写入本区 RocksDB |
| GAME 出征 / 召回 | 玩家兵力和英雄预留、行军和阶段任务 | 按玩家串行，核对当前状态及版本；出征时间与结果随回执持久化 |
| GAME 到期任务 | 行军、下一阶段的待办、货物或玩家资产 | 重新检查任务、代次和预留，同批标记完成或阻断 |
| GAME 准备 NPC 战斗 | 行军进入等待、固定战斗快照、待计算索引 | 到达任务完成和战斗准备同批写入，随后异步派发 |
| GAME 应用 Worker 结果 | 战报、玩家伤亡、幸存队伍、返城任务 | 通过所属玩家邮箱核对战果，同批标记结算、移除待计算索引；返城时入账资源、释放英雄和槽位 |
| GAME 投影线程 | 独立 MySQL 中的归档、对象查询快照、连续游标 | 按 realmId 和原卷 ID 绑定，一批归档与游标在同一 InnoDB 事务提交。 |

Worker 计算快照，Gateway 转发请求，两者均无游戏状态写权。每个区服的日志序号、对象预期版本、系统回执与业务变更一起提交。UC 持有账号库连接池。MySQL 游戏投影器只消费已提交日志，把投影数据与连续消费位置写入同一 SQL 事务。PVP、联盟、支付发货和 GM 修复命令各自需要补齐对象资格、权限与业务幂等键。[存储提交入口](../slg_game/src/main/java/com/slg/game/storage/RealmJournal.java) · [生产任务](production-task-plan.md)
