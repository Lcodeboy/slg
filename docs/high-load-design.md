# 单区容量与故障验收

单区目标为 10,000 在线、峰值 2,000 条业务命令/秒。目前已实现有界网关调用、单玩家/全区邮箱限额、独立冷加载池、到期待办分页扫描、Worker 在途上限和计算队列。容量结论须基于当前 RocksDB 架构、完整行军和后台结算负载。

| 场景 | 需要记录的结果 |
| --- | --- |
| 万连接与混合命令 | 分散账号和单热点分别施压，记录成功吞吐、拒绝、P50/P95/P99；区分客户端超时与确实未受理 |
| 冷加载与驱逐 | 控制热玩家比例，记录每秒首次读盘、加载等待、驻留名额和 JVM 堆 / RocksDB 原生内存 |
| 采集、到达与返城 | 测量出征与同一时间大量到期任务竞争时的提交延迟、任务延迟和资产守恒 |
| NPC 计算峰值 | 测量 GAME 在途数、Worker CPU / 队列、拒绝率、原卷中最老积压时长及恢复后排空速度 |
| GAME 重启与 Worker 停机 | 保留原卷并强杀进程，核对已确认操作、待办和回执。恢复时测就绪时间与积压追赶时间 |
| 投影、广播与热点攻城 | 已用真实停库验证顺序追赶与积压限流。仍需测追赶吞吐、AOI 高密度视野、多对象竞争与磁盘水位 |

当前隔离压测工具会建立临时卷、启动 Gateway / GAME / Worker，在测试区建角，复用已认证 TCP 连接，以固定到达速率发起命令。示例轻载烟测如下。

```sh
python3 scripts/load-test.py --transport tcp --workload march-mix --players 16 --connections 8 --rate 20 --duration 5
```

本机回环明文 TCP 烟测使用上述参数，三个 JVM 各设最大堆 160 MiB。16 个预建角色中有 8 个账号保持长连接。5 秒内完成 100 条命令（20 次出征、80 次读取），从计划发送到收到响应的 P50 / P95 / P99 分别为 5.8 / 11.0 / 20.3 ms，结束时 8 条连接仍可用。该场景覆盖连接复用、混合命令和测量链路。容量验收还须固定 JVM 堆、机器 CPU/盘型、数据规模、持续时间、请求分布、SLA 和拒绝预算后实测。[强杀验证](../scripts/check-realm-march.py) · [生产验收里程碑](production-task-plan.md)
